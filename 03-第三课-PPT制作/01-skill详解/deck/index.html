结构 · 上下文规则

Progressive Disclosure · 渐进式披露原则

上下文是稀缺资源，信息按需加载

为什么必须分层

AI 每轮对话的上下文窗口有限且昂贵。若把所有技能的全部内容常驻，几个技能就能挤爆窗口。分层的本质：只让"当前这一刻需要的信息"占用上下文。

对作者的要求

① SKILL.md 必须精简，细节到 references体现；② 同一条信息只在 SKILL.md 或 references 出现一次，不重复存放；③ 代码执行的结果才进上下文，代码本身不进。

触发链

用户说了一句话 → AI 扫描所有技能的元数据（第 1 层）→ 命中则加载 SKILL.md 正文（第 2 层）→ 按正文指示，在干活过程中读取具体资源（第 3 层）。

第 1 层 · 元数据（name + description）
始终常驻 · 约 100 词 · 每个技能都占一点，决定"何时触发"
第 2 层 · SKILL.md 正文
触发时才加载 · 控制在 5k 词内 · 核心工作流程与资源地图
第 3 层 · 资源文件
干活时按需 · 体量基本无上限 · scripts 执行 / references 读入 / assets 使用
机制 · 三级加载
右侧漏斗图是本页核心：宽度代表上下文占用。第一层每个技能都在交"门票钱"，所以 description 的写法直接决定技能会不会被想起来用。

Case 2 · 代码驱动的真实技能

个股与概念板块K线相似度分析 · 目录拆解

share_concept_analysis/
├─ skill.md # 主控文档
├─ scripts/ # 01-06 编号脚本 + 工具库
   ├─ 01_fetch_stock_data.py # 取个股K线
   ├─ 02_fetch_concept_data.py # 取概念指数
   ├─ 03_search_concepts.py # 按主业搜概念
   ├─ 04_align_and_merge.py # 交易日对齐
   ├─ 05_calculate_similarity.py # 7维计算
   ├─ 06_run_full_analysis.py # 一键总控
   └─ utils.py # 权重与评分
├─ references/ # 理论·API调用方法·踩坑
├─ agents/ # 分析师角色卡
├─ assets/ # 模板与示例
└─ output/ # 分析产物

skill.md · 元数据

name：概念板块K线相似度分析；description：分析个股与同花顺概念板块指数的 K 线形态相似度，7 维指标量化排序；dependencies：依赖。

为什么需要 6+1 个脚本

K线抓取、概念搜索、日期对齐、等指标计算全是有唯一正确答案的确定性任务——编号即执行顺序（01→06），utils.py 存放共用权重与评分函数。

各目录分工

references 存相似度理论、API 文档（按需读）、操作过程中踩的坑；agents 存分析师人设（必要时启用）；assets 存批量分析模板；output 隔离产物，不污染技能本体。

案例 · 结构
这是我自建的技能，没使用skill-creator创建，而是在和AI每轮的互动过程中总结的。这个流程有唯一正确的答案，因此适合用代码控制。

Case 2 · 其他文件到底装了什么

references / agents / assets / output 逐文件拆解

references/ · 按需查阅的知识

  • api_references.md：这里面是数据来源的记载（同花顺API——akshare / 腾讯财经API），如何调用，有什么限制。
  • similarity_theory.md：7 个指标的数学公式与解读口径（如 r^2 > 0.5 为强相关）——说明"为什么这么算"
  • known_issues.md：踩坑档案——同花顺API有速率和使用次数限制，东方财富 API 已被永久屏蔽，防止重蹈覆辙
  • analyzed_stocks.md：已分析标的知识库，概念→个股反向索引（如"盐湖提锂→赣锋锂业 r^2 = 0.7434"），新闻驱动板块异动时快速反查关联个股

agents/ · AI 的判断空间

  • concept_analyst_agent.md："概念板块K线分析师"角色卡——是否启用子代理完成任务，对不熟悉的股票先研究主营业务再筛选概念。

assets/ · 复用与示范

  • stock_analysis_template.py：批量分析模板，只改 股票代码 / 股票名称 / 概念板块 三个配置即可复用全流程
  • example_analysis.md：完整的流程记录，以工业富联为例，完整分析各个概念得分。

output/ · 产物隔离区

  • {股票}_aligned_data.csv：对齐后的共同交易日收盘价，供复查与二次分析
  • {股票}_similarity_results.csv：各概念 7 维得分与综合排名——分析结论的最终载体。产物与技能本体分离，重跑不污染技能
案例 · 文件详解
四个目录对应四种角色：references 是知识库（理论+API+踩坑+历史成果），agents 是判断外包，assets 是复用模板与教学示范，output 是产物隔离。

Case 2 · 流程如何被代码"焊死"

脚本编号即流程，AI 无权自由发挥

Step 1 获取数据

腾讯财经API + akshare/THS，失败自动重试 5 次

→
Step 2 日期对齐

取所有序列的共同交易日，剔除缺失

→
Step 3 7维计算

Pearson / 余弦 / 方向 / 形态 / DTW / 振幅 / 回撤

→
Step 4 加权评分

Min-Max 归一化 → 加权求和 → 排序输出 CSV

硬控手段 · 入口与权重都焊死

skill.md 指定唯一入口，AI 只负责拼参数：

python scripts/06_run_full_analysis.py --code sh601138 --name "工业富联"

代码控制的好处：

1. 大幅度减少Token的消耗；

2. 不同大模型运行结果依然相同，不会出现漂移。

Practice · 零代码课堂练习（使用 /skill-creator 制作）

meeting-minutes 会议纪要整理助手

meeting-minutes/
├─ SKILL.md # 整理流程
└─ references/
   ├─ template.md # 纪要模板
   ├─ glossary.md # 公司黑话
   └─ examples.md # 满分样例
用途：把凌乱的会议速记，整理成有结论、有待办、有负责人的正式纪要。

SKILL.md 四步流程

读速记稿 → 查 glossary 懂术语 → 按 template 重组 → 自检字数与格式。铁律：待办必须有负责人和时间，原文没写就标「待确认」，禁止编造。

glossary.md 教学灵魂

AI 不知道「昆仑」是项目、「老王」是采购部王建国。skill 的用途 = 给 AI 补上它不知道的你的私有知识。

examples.md 手感样板

写一百遍「要简洁」，不如给一组改之前 vs 改之后。规则写进 references，手感交给样例。

练习 · 任务说明
制作方式：对 WorkBuddy 说"使用 /skill-creator 帮我创建 meeting-minutes 技能"，按流程生成骨架后填入下一页素材。
