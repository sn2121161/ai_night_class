# Molecule Shop 后端功能提示词

这不是技术方案文档，而是一组可以直接交给代码助手的自然语言提示词。建议一次只做一个功能，做完就运行测试和启动项目确认，不要一次把所有提示词都交给模型。

## 使用前先告诉代码助手

```text
项目目录是 "你的前端目录"。

请在现有项目中开发，不要新建一个项目，不要删除已有功能，也不要修改 README.md 中与本次需求无关的内容。

后端使用 Python + FastAPI，数据库使用 PostgreSQL，前端已经有 React 页面。请先查看现有目录、现有接口和数据库表，再开始改动。每次改动后都要：
1. 写或更新相关测试；
2. 运行后端测试；
3. 如果改了前端，也运行前端构建；
4. 告诉我改了哪些文件、测试结果和如何在 Docker 中生效。

不要把密码、邮箱授权码、JWT 密钥、数据库密码、飞书密钥写进代码或提交到 Git。

很重要：不要假设我的电脑已经安装 Docker、PostgreSQL 或已经存在 `.env`。在动手前先检查这些条件；如果 Docker 不可用，就使用下面的“无 Docker 本地学习模式”。不要因为配置缺失而偷偷换成内存数据库、假接口或演示模式；必须明确告诉我当前使用的是哪种数据库、数据保存在哪个文件，以及是否写入演示数据。
```

## 0. 没有 Docker 也能启动：先做本地学习模式

把这一段作为整个项目的**第一条提示词**交给代码助手。它解决“没有 Docker、没有 `.env`、5600 虽然监听但不知道跑的是什么”的问题。

```text
请先为这个项目做好“无 Docker 本地学习模式”。我的电脑可能没有 Docker，也没有 PostgreSQL，更没有 backend/.env。

请不要假设环境已经准备好，也不要因为缺配置就自动使用假数据或演示模式。

请完成下面这些事情：

1. 在 backend 目录增加一个简单的初始化命令，例如：
   python init_local.py
   它在 backend/.env 不存在时自动创建它；如果文件已经存在，不能覆盖，必须提示我。

2. 这个初始化命令要生成安全的随机 JWT 密钥和银行卡加密密钥，不要使用固定的示例密钥。无 Docker 模式默认使用本地 SQLite 文件：
   DATABASE_URL=sqlite:///./shop.db
   AUTO_CREATE_SCHEMA=true
   SEED_DEMO_DATA=false
   FRONTEND_URL=http://localhost:3000

3. 请增加一个单独的、明确的初始化命令，例如：
   python init_local.py --seed
   只有我主动加 --seed 时，才创建演示管理员、苯项链和示例留言。普通启动绝不能自动灌入演示数据。

4. 启动前检查 .env 是否存在、银行卡加密密钥是否有效、数据库能否连接。如果失败，要用中文打印明确原因和下一步命令，不能静默退回到假数据或内存数据库。

5. 请给我两套明确命令：
   - 无 Docker 的本地学习模式：创建 .env、安装依赖、初始化 SQLite、启动后端；
   - 有 Docker 的完整模式：启动 PostgreSQL、后端和前端。

6. 增加 GET /health/details，只返回不敏感信息：当前使用的数据库类型（sqlite 或 postgresql）、演示数据是否开启、服务环境名称。不要返回密码、连接串、密钥或 token。

7. 写测试：没有 .env 时初始化命令能创建文件；已有 .env 不会被覆盖；普通初始化不会写演示数据；带 --seed 才会写演示数据。

做完后告诉我：我现在运行的 5600 后端使用什么数据库，数据文件在哪里，以及它是否有演示数据。
```

学生在没有 Docker 的电脑上，应先执行代码助手生成的初始化命令，再启动后端。不要直接只运行 `uvicorn`。

## 1. 先搭好本地数据库和后端启动

```text
请帮我检查并完善这个商城项目的本地后端启动方式。

我希望支持两种启动方式：
- 电脑安装了 Docker 时，用 Docker 一次启动三个服务：
- PostgreSQL 数据库；
- FastAPI 后端；
- 前端页面。
- 电脑没有 Docker 时，使用 SQLite 本地文件运行后端学习版，不要求安装 PostgreSQL。

浏览器访问 http://localhost:3000。
后端健康检查地址为 http://127.0.0.1:5600/health。
数据库不要直接暴露到电脑端口，后端只允许本机通过 127.0.0.1:5600 访问。

请准备 `.env.example`，里面只放变量名和示例值，不放真实密码。还要提供上一步提到的初始化命令，首次运行时自动生成真正的 `backend/.env`。` .env.example` 只是参考文件，不能假设程序会自动读取它。

默认不要自动创建演示数据。只有用户主动执行带 `--seed` 的初始化命令，或明确把 `SEED_DEMO_DATA=true` 写入 `.env`，才允许创建演示管理员、商品和留言。启动时请在控制台打印“数据库：SQLite/PostgreSQL；演示数据：开启/关闭”。

数据库使用 PostgreSQL 的 shop schema。请使用 migration 管理建表和后续改表；不要要求我手动执行 SQL。请给我明确的启动、更新数据库、看日志、停止服务命令。
```

验收：
- 有 Docker：执行 `docker compose up -d --build` 和数据库 migration 后，三个容器都正常；
- 无 Docker：执行初始化命令和后端启动命令后，SQLite 数据文件已经创建；
- 两种方式的健康检查都返回 `{"status":"ok"}`；`/health/details` 能明确说明当前数据库和演示数据状态。

## 5. 忘记密码和邮箱找回

```text
请实现忘记密码功能，并和登录页的“忘记密码？”按钮连起来。

流程如下：
1. 用户在找回密码页面输入注册邮箱；
2. 后端生成一次性的重置链接并发到邮箱；
3. 链接 30 分钟内有效，只能使用一次；
4. 用户打开链接后输入新密码和确认密码；
5. 密码修改成功后，旧的登录状态全部失效。

安全要求：
- 数据库只能保存重置码的加密摘要，不能保存完整重置码；
- 再次申请时，让该用户之前未使用的重置链接失效；
- 邮箱不存在时也返回“如果邮箱已注册，请查收邮件”这种统一文案，不要暴露账号是否存在；
- 邮件里只放重置链接和有效期提示，不能放密码；
- 没配置 SMTP 时记录服务端日志，但不要假装已经发出真实邮件。

前端需要有 /forgot-password 和 /reset-password 页面，使用 Ant Design 风格按钮和表单。

请写测试：重置链接能改密码、旧密码不能再登录、旧登录状态失效、链接不能重复使用、超过 30 分钟不能使用。
```

### QQ 邮箱配置提示

```text
请不要把 QQ 邮箱授权码写入代码。请在 backend/.env.example 中保留这些变量，并在文档里解释填写方法：

FRONTEND_URL=http://localhost:3000
SMTP_HOST=smtp.qq.com
SMTP_PORT=587
SMTP_USERNAME=你的QQ邮箱地址
SMTP_PASSWORD=QQ邮箱SMTP授权码
SMTP_FROM=你的QQ邮箱地址
SMTP_STARTTLS=true

当前代码使用 587 加 STARTTLS。SMTP_PASSWORD 必须提醒用户填写 QQ 邮箱生成的授权码，不是 QQ 登录密码。

如果本地没有公网域名，重置邮件里的 localhost 链接只能在运行前端的同一台电脑上打开；部署到服务器后要把 FRONTEND_URL 改成实际 HTTPS 域名。
```

## 15. 数据库表应该怎么让代码助手创建

```text
请为商城设计数据库并使用 migration 创建，不要让我手动复制 SQL。

至少需要这些数据：
- 用户：用户名、邮箱、密码加密结果、角色、状态、登录版本、创建时间；
- 密码重置链接：属于哪个用户、加密后的重置码、过期时间、是否已用；
- 商品和库存；
- 购物车；
- 订单、订单商品快照、订单配送/地址/支付快照；
- 默认地址；
- 保存的银行卡；
- 商品留言和留言图片；
```
