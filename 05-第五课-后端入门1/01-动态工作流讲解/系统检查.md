本次任务只做检查和报告，不安装、不升级、不卸载、不修复、不修改任何项目源文件或配置。

## 一、检查范围

只检查当前代码已经实际接入并正在使用的环境，包括：

1. 项目启动所需的运行时
2. 当前启动脚本使用的工具
3. 当前依赖清单中声明的依赖
4. 当前 package.json、pyproject.toml 等文件中已经配置的构建、Lint、类型检查和测试工具
5. 当前代码运行时真正必需的环境变量
6. 当前项目实际依赖的本地服务

不要检查或报告以下内容：

- 只出现在技术规划、架构方向或未来需求中的工具
- 当前代码尚未接入的工具或服务
- 当前启动、构建、测试均不需要的可选工具
- 文档中提到但当前依赖、代码、配置和脚本均未使用的技术
- 未来可能使用的部署环境

例如：如果 Docker、Docker Compose、Celery、Redis、S3、Alembic、Playwright、Vitest、Prettier 或 mypy 当前没有出现在实际启动流程、依赖清单或可执行脚本中，就完全忽略，不要把它们列为缺失项，也不要列入“规划中”或“可选项”。

## 二、判断依据
按以下优先级确定当前项目真正需要的环境：

1. 当前实际使用的启动脚本，例如：
   - start.sh
   - start.bat
   - Makefile
   - Taskfile
   - package.json scripts
2. 当前依赖和版本配置，例如：
   - package.json
   - pnpm-lock.yaml
   - package-lock.json
   - yarn.lock
   - pyproject.toml
   - uv.lock
   - requirements.txt
   - .python-version
   - .nvmrc
   - .node-version
   - .tool-versions
3. 当前 CI 中实际执行的命令
4. README 中明确描述的当前启动方式
5. AGENTS.md、设计文档和架构文档仅作为辅助信息

如果架构文档与实际启动脚本或依赖清单不一致，以当前可执行代码、启动脚本、依赖清单和锁文件为准。

不得仅根据架构文档中出现了某个工具，就判定本机必须安装该工具。

## 三、必须检查的核心环境

无论这些环境是否缺失，最终都必须显示检查结果：

- 操作系统和 CPU 架构
- Node.js
- npm
- pnpm（规定项目使用 pnpm）
- Corepack（如果项目可能通过 Corepack调用 pnpm）
- Python
- 项目 Python 虚拟环境
- pip 或项目当前实际使用的 Python 包管理方式，python包管理方式使用uv
- database，sqlite
- 当前启动脚本要求的其他核心命令

对每一项检查：

- 当前版本
- 项目要求版本
- 实际安装位置
- 是否符合要求
- 判断依据
